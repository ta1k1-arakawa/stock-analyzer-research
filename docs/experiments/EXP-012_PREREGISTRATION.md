## 背景

- EXP-009 の S（合成スコア＝B/P 順位＋予想ROE 順位）は事前登録の3基準すべてに合格し、前向き検証中。EXP-010 では決算モメンタム脚の追加（バリアントA）が同じ3基準に合格した
- 予想ROEは、東証の資本コスト・PBR改善圧力のもとで、自社株買いやレバレッジによって「作れる」数字になってきている。粗利益／総資産（GPA）はレバレッジや自社株買いでは水増しできない
- 日本市場での直接比較でも GPA は ROE より有効とされる（SuMi TRUST の日本株ファクター検証、2007-24。Liu–Yadohisa でも粗利益ベースの収益性が日本株リターンを予測）
- 一方で予想ROEは会社予想という先行情報を含む。GPA（実績値）への全面置換はその情報を失う恐れがあるため、ブレンドを先に、置換を次に試す

## 仮説

収益性脚に GPA をブレンド（または置換）すると、ロング・ショートのスプレッドが S より改善する（年率 ÷ 最大ドローダウンの大きさで判定）。

## データ取得（新規分）と実現可能性ゲート

- 既存の EXP-002 キャッシュ（/v2/fins/summary）には売上総利益の項目がない（Sales・OP・OdP・NP・TA 等のみ）。GPA の分子は /v2/fins/details でのみ取得できる
- /v2/fins/details は **Premium プラン（¥16,500/月）でのみ利用可能**（Standard では取得不可。2026-10-29 に J-Quants 公式のプラン別仕様で確認）。したがって本実験には「Premium に1か月だけ加入して 306銘柄分を取得し、Standard に戻す」一時的コスト ¥16,500 が前提になる。取得自体はレート制限（60回/分）の範囲で1日あれば終わる規模
- 取得は experiments/exp012_fetch_details.py で行う（exp002_fetch.py と同方式：銘柄ごとに全期間、APIキーは環境変数 JQUANTS_API_KEY、原データを data/jquants_exp012_details/ に保存し、SHA-256 マニフェストを残す。再配布不可データのため git 管理外）
- バックテストに進む前のゲート（どちらかを満たさなければ「データ都合で中止」と記録し、代替指標への差し替えはしない）：
  1. 現在の契約で /v2/fins/details が実際に取得できること（Premium 加入後、1銘柄で疎通確認）
  2. 下記定義で GPA が計算できる銘柄の割合が、評価期間中の中央値の日で 60% 以上あること

## GPA の定義（すべて開示日ベースの point-in-time）

- 対象レコード：/v2/fins/details のうち DocType に `FYFinancialStatements` を含むもの（通期決算短信の財務諸表）
- 同一銘柄・同一事業年度（FS 内の `Current fiscal year end date, DEI` で識別）について、連結（DocType に `_Consolidated_` を含む）を優先し、同区分内では開示日時・開示番号が最新のものを採用する（訂正開示は新しい開示として上書きされる＝その開示日以降の値が変わる）
- 売上総利益 GP：FS の `Gross profit (loss)`（日本基準）を優先し、なければ `FS` の `Gross profit`（IFRS 等）を使う。どちらのラベルで取れたかは結果文書に記録する
- 総資産 TA：同じ開示番号（DiscNo）の EXP-002 キャッシュ（/v2/fins/summary）レコードの `TA`。対応レコードがない、または TA が空の事業年度は GPA 未定義とする
- GPA ＝ GP ÷ TA。その銘柄の GPA は採用レコードの DiscDate から有効になり、次の事業年度の GPA に更新されるまで維持される（EXP-003 の signals と同じ開示日の付け方）
- GPA が未定義の銘柄（銀行・証券など売上総利益の概念がない業種、未上場期間、データ欠損）は、その日の GPA 順位を中立の 0.5 とする

## 案

- ベースラインは EXP-009 の S と同一条件：対象期間・ユニバース（約306銘柄）・資金200万円・コストと逆日歩ストレス・エンジンは EXP-009／EXP-010 のものをそのまま再利用し、変更しない。比較対象の S は同一キャッシュ上でスクリプト内に再計算する（EXP-010 と同じ）
- 各脚は日次横断パーセンタイル順位に変換してから合成する（EXP-010 の脚の扱いと同一）
- バリアントA（ブレンド）：収益性脚 ＝（予想ROE順位 ＋ GPA順位）÷ 2、合成スコア ＝（B/P順位 ＋ 収益性脚）÷ 2
- バリアントB（スワップ）：合成スコア ＝（B/P順位 ＋ GPA順位）÷ 2（予想ROE脚を GPA に全面置換）
- ロングは合成スコア上位、ショートは下位（S と同じ仕組み）。他の脚・条件は同一にして、収益性脚の変更だけの増分を測る

## 判定基準（EXP-009 の3基準にならう。すべて満たせば「有望」）

1. 両方の期間（前半 2017-01-04..2021-12-30、後半 2022-01-04..2026-09-25）で、基本費用の新案の損益 > 0
2. 両方の期間で、新案の「年率 ÷ 最大ドローダウンの大きさ」が S より大きい
3. 全期間（2017-01-04..2026-09-25）のストレス費用でも、新案の損益 > 0 かつ 2 の比が S より大きい

- 損益そのものが S を上回ることは求めない（EXP-009 と同じ理由）
- バリアントA・Bは別々に判定する。どちらか一方でも3基準を満たせば「有望」とし、前向き検証の候補にする（実際のお金で使うかは人間が決める）

## 最大のリスク

- Premium の一時コスト（¥16,500）が前提。それでも GPA の増分がゼロなら費用だけが残る
- 売上総利益を取れない業種（金融など）が中立扱いになるため、実質のユニバースが縮む
- GPA は実績値（trailing）であり、予想ROEの先行情報を失う。特にバリアントBで顕在化しうる
- GPA 脚が B/P 脚や予想ROE脚と相関し、増分がゼロになる可能性
