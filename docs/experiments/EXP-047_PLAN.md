# EXP-047 計画: A_rst(EXP-046)をフォワードのペーパーポートフォリオとして追加し、再現検証する

EXP-011 と同型の実装検証であり、新しい収益性テストではない。ユーザーは 2026-11-01 にペーパー追加を承認した。実弾 V とライブの A は変更しない。

## 変更内容(exp004_forward.py / free_data.py)

1. `PORTFOLIOS` に `"AR"` を追加。`load_state` は A と同じ型(ロング+ショート、realized)で AR を種付けする(既存ライブ状態では次回の注文書から新規開始、初期資金 ¥400,000)
2. フラグ計算 `restate_flags(today)`: `forward/restate_events.csv`(date, code, title)から、開示日 < today かつ開示日 ≥ today − 24 か月の「数値データ訂正×決算短信」イベントが 2 件以上の銘柄集合を返す(EXP-046 の定義と同一)
3. 注文生成: `rank["AR"]` = `rank["A"]` からフラグ銘柄を除いたもの(ロング側)。**ショート側は A のランキングを使う**(EXP-046 の設計通り)
4. データフィード: `free_data.update_restate_events(codes, days=10)` を `update_data` から呼ぶ。TDnet 日次リスト(既存の `list_rows`)から該当タイトルを抽出し CSV に追記(重複排除)。初期シードはヤノシンのタイトルコーパスから 2023-11-01 以降のイベントで作成する

## 再現検証(exp047_replay_forward.py、EXP-011 のハーネス方式)

- スクラッチ状態で 2022-01-04〜2026-09-25 を日次ステップ(対象 S / A / AR、M と L は EXP-011 と同じ理由で除外)
- イベントファイルはコーパスから作った全期間版をスクラッチに置く
- チェック(実装の健全性であり新しい判定ではない):
  1. コントロール: リプレイの A の最終損益が EXP-046 バックテスト後半の A(+¥4,160,686 を ¥400,000 換算 = +¥832,137)と ±5% 以内で一致
  2. AR の最終損益が A を上回り、AR/A の損益比がバックテストの比(1.176)の ±10% 以内
- どちらかが外れた場合は実装差異として調査し、計画の範囲で直す。バックテスト側(EXP-046)は変更しない

## 運用

追加後は平日夕方のフォワード報告に AR の評価額が加わる。AR はペーパーであり、実弾判断の対象にしない。
