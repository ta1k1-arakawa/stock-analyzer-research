# EXP-046 事前登録: 決算短信の数値訂正を繰り返す銘柄のロング除外

第 3 弾スイープ 6 位。第 5 位(監査人の辞任フラグ)は、辞任/任期満了の判別に必要な開示本文が過去分について取得不能(ヤノシン API に文書エンドポイントなし・TDnet 公式は直近のみ・EDINET 臨時報告書は保存 1–2 年)なため、タイトルだけでは過半を誤分類する。**EXP-045 はデータ不能として実行しない。** 本実験は第 6 位を単独で検証する。

## 仮説

決算短信の数値訂正を繰り返す企業は開示統制が弱く、その後のパフォーマンスが劣る。ロング側から繰り返し訂正する銘柄を除外すると A が改善する。

## データ(実測済み)

- TDnet タイトルコーパス(306 銘柄、2016-10〜2026-09、33,939 件)
- 訂正タイトル 1,077 件、うち決算短信の訂正 502 件、「数値データ訂正」マーカー付き 302 件

## 信号(固定)

- 「数値訂正イベント」= タイトルに「数値データ訂正」を含み、かつ「決算短信」を含む開示
- **既知の汚染を宣言する**: このマーカーには XBRL データファイルの修正(財務数値自体の訂正ではないもの)が混ざる。分離はタイトルからは不能であり、このノイズ込みで検証する
- フラグ: 直近 24 か月(暦日)に数値訂正イベントが **2 件以上**の銘柄

## バリアント

- A_rst: ロング側 = A の有効銘柄からフラグ銘柄を除外(フラグは開示日の翌営業日から有効)。ショート側 = A のまま(simulate2)。これ以外は A と同一

## 判定

A に対する標準 3 基準(両半分黒字/比率が両半分で A 超え/全期間ストレス)。フラグ銘柄数と除外頻度を結果に併記する。

## リスク(登録済み)

- 日本のイベント証拠は矛盾している(訂正開示に正の反応を示した研究もある)。ペナルティ専用設計であり、効いても小さい見込み
- XBRL 修正の混入で信号が薄まる方向のバイアスがある
