# EXP-012 補遺1（AMENDMENT_1）：GPA のデータソースを EDINET（無料）に変更

```text
date=2026-10-29
reason=事前登録のコミット後・実行前に、ユーザーが J-Quants Premium 契約を明確に拒否したため（2026-10-29）。売上総利益の取得手段を Premium 専用 API から無料の EDINET API に切り替える。結果を見る前の変更であり、仮説・バリアント・判定基準に変更はない
```

## 変更1：データソース

- 変更前：J-Quants /v2/fins/details（Premium プラン ¥16,500/月が必要）で売上総利益を取得し、取得スクリプトは experiments/exp012_fetch_details.py
- 変更後：EDINET API v2（金融庁、無料。APIキーの発行登録のみ必要）から取得する。取得スクリプトは experiments/exp012_fetch_edinet.py に改める
- 取得方法：書類一覧 API（documents.json、type=2）で 2016-01-01..2026-09-25 の各日の提出書類を走査し、対象306銘柄（secCode 一致）・docTypeCode 120（有価証券報告書）かつ csvFlag=1 の書類について、書類取得 API（type=5、XBRL→CSV変換）を取得する。リクエスト間隔は数秒空ける（EDINET 側の暗黙のレート制限に配慮）。取得は数時間規模のバッチになるため、中断・再開できる設計にする
- APIキーは環境変数 EDINET_API_KEY から読む（exp002_fetch.py の JQUANTS_API_KEY と同じ方式。コード・ログに残さない）
- 原データは data/jquants_exp012_details/ ではなく data/edinet_exp012/ に保存し、SHA-256 マニフェストを残す（git 管理外）

## 変更2：GPA の構成（提出日ベースに読み替え）

事前登録の GPA 定義（通期のみ・連結優先・訂正は新しい開示として上書き・中立 0.5 の扱い）は維持し、出典に合わせて次を読み替える：

- 対象書類：決算短信の財務諸表 → 有価証券報告書（docTypeCode 120）。訂正有価証券報告書（130）は同じ事業年度の値をその提出日から上書きする
- 事業年度の識別：書類一覧の periodEnd（決算期末日）
- 売上総利益 GP：CSV の「売上総利益」に相当する要素ID（会計基準ごとに要素IDが異なるため、候補IDのリストをコードに固定し、実データでの取得状況を結果文書に記録する）。連結・当期の値を用いる
- 総資産 TA：同一書類の総資産（連結）。事前登録の「同一 DiscNo の summary の TA」は使わない（出典が変わり DiscNo 対応がなくなるため）
- 利用可能日：DiscDate → EDINET への提出日（書類一覧の submitDateTime の日付）。有価証券報告書は決算短信より後に提出されるため、GPA の反映は事前登録の想定より遅くなる。これはデータの制約として受け入れる（先読みはしない）

## 変更3：実現可能性ゲート

- ゲート1（Premium 疎通確認）→ EDINET APIキーの無料発行と、1銘柄での CSV 取得の疎通確認に読み替える
- ゲート2（GPA を計算できる銘柄の割合が中央値の日で 60% 以上）は変更なし

## 変更なしの確認事項

- 仮説、バリアントA（ブレンド）・バリアントB（スワップ）の定義、判定基準（EXP-009 の3基準）、対象期間・ユニバース・資金・コスト・ストレス、エンジンの再利用方針は事前登録の通り
- 代替指標への黙示の差し替えをしない原則も変更なし（営業利益／総資産などを試す場合は別実験として新規登録する）
