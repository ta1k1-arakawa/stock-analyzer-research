## 1. 全文取得（スコープ）

- 対象: ゲートのセンサス `~/workspace/exp107_gates/gate1_filings.json` の全 **2,921件**（306銘柄、期末年2016–2026、有報 DocTypeCode 120、DocId・提出日・期末日付き）。センサス自体はゲートで EDINET 実リストと2シーズン分を交差検証済み（214/214・215/215銘柄で完全一致）。
- 取得物: EDINET API の type-5 CSV zip（`documents/{docID}?type=5`、custom.edinet ヘルパー経由）。
- 保存先: `~/workspace/exp107_run/zips/{docID}.zip`。ゲートで取得済みのサンプル580件（`~/workspace/exp107_gates/zips/`）はコピーして再利用し、残り約2,341件を新規取得する。
- 再開可能な取得パターン（ゲートの gate1_download.py と同型）: 既存の非空 zip（>1,000 bytes）はスキップ、状態JSONに進捗を記録、リクエスト間隔1.0秒、429/5xx はバックオフ。起動は `setsid nohup ... < /dev/null &`（VM再起動でプロセスが死ぬ前提）。完了判定はプロセスの生死ではなく件数で行う: 取得済み+スキップ = 2,921、失敗は docID リストで明示する。

## 2. 抽出とペア構築

- 抽出はゲートの gate1_extract.py のロジックをそのまま再利用する（UTF-16 TSV、要素名はローカル名照合、セクションごとに最長値）。取り出すのはリスク欄 `BusinessRisksTextBlock`（主）と MD&A 要素群（参考診断用）。
- 出力: 届出ごとの抽出結果テーブル（code、期末年、提出日、docID、リスク欄の文字数、MD&Aの文字数、テキスト本体は信号構築用に run ディレクトリ内へ保存）。
- ペア: 同一銘柄で期末年が連続する届出同士。両年のリスク欄が取れたペアについて、空白除去→文字バイグラム集合→Jaccard を計算し、当年側届出に (code, 提出日, sim_risk, sim_mda参考) として付ける。
- 実行前の健全性チェック（リターンは見ない）:
  - ペア数が約2,500–2,650件の範囲にあること。
  - リスク欄 Jaccard の分布がゲートサンプル（中央値0.925、IQR 0.159）と大きく乖離しないこと。
  - 年別の有効化銘柄数（2017年は数十銘柄、2018年以降は約290銘柄）が想定どおりであること。

## 3. 実行スクリプト概要（exp107_run/exp107_lazy.py、未作成）

- 枠組みは exp105_run と同型: exp003_rotation / exp009_long_short / exp010_earnings_momentum のコピーを run ディレクトリに置き、EXP-002キャッシュ（~/workspace/cache/jquants_exp002/）を読む。期間 first_half 2017-01-04..2021-12-30 / second_half 2022-01-04..2026-09-25、コスト base（片道0.0003・借株3%/年）/ stress（0.0010・5%/年）、予算¥2,000,000、PER_TRANCHE 2 × 10トランシェ、20営業日保有、2営業日ごとリバランス、翌寄付執行。
- 信号パネル: ペアテーブルから日次×銘柄の状態行列を作る（提出日 < t の最新届出の sim。提出日当日からは使わない）。Aの有効集合と交差させ、状態あり銘柄内でパーセントライルランク化 → lp_r、状態なしは0.5。
- スコア A_lp = (comp_r + mom_r + lp_r)/3 で E9.simulate（ロング1.0・ショート0.5）。S・A も同一スクリプトで再計算し、A が事前登録の現行値（FH +¥970,644 / 0.348、SH +¥4,133,557 / 1.584、フルstress比率0.428）を再現しなければ実行無効として止める。
- 出力: result.json（各期間×コストの利益・年率・最大DD・比率、標準3基準の判定、MD&A類似度を使った場合の参考診断は付けない＝登録外の変種は回さない）。
