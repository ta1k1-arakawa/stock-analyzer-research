## 仮説

引け価格がその日の終日VWAP（出来高加重の平均約定価格）を大きく上回る銘柄は、その日の買いフローが平均コストを大きく上回る水準まで価格を押し上げた状態であり、翌営業日にかけて平均へ回帰する。部分時間VWAP（10:00 / 11:00 時点、EXP-127 系）とは別に、終日VWAPという未使用の特徴量で独立に測定し、既知の強い日フェードセル（EXP-133 / 136 / 137 / 139 / 140）との重なり監査を通過したため登録する。前方データで判定する。

## 信号の固定

- **ユニバース**: 306 銘柄ユニバース（EXP-002 キャッシュの対象銘柄）で開始する。全市場への拡張は、中間集計で実績コスト後平均がプラスを維持している場合にのみ、本書への追記（amendment）として登録した上で行う。
- **イベントの定義**: 取引日 t について、(引け価格 ÷ (当日売買代金 ÷ 当日出来高) −1) ≥ +2% を満たす銘柄・日をイベントとする。同一銘柄・同一日は最大1イベント。分割疑い日、出来高ゼロの日、引け価格が得られない日は対象外。
- **エントリー**: **取引日 t の引け価格で売る（ショート）**。前方実装では引け価格をエントリー価格として台帳に記録する。
- **エグジット**: **翌営業日の引け価格**で全量を買い戻す。翌営業日の引け価格が得られない場合は、最初に得られた後続の引け価格まで繰り延べて買い戻し、その旨を台帳に記録する（繰延決済）。決済日がイベント日から10暦日を超える場合は対象外として除外する。
- **価格**: 損益率は未調整価格どうしの比率とする。保有期間中に株式分割・併合の効力が発生したイベントは、調整済み価格ベースの比率を正として併記する。
- **ベンチマーク**: 各イベントについて、同窓（当日引け→翌営業日引け）の TOPIX 変化率を記録し、超過リターン = イベント損益率 + 同窓 TOPIX 変化率（ショートのため）とする。フォールバック窓は定義しない。同窓 TOPIX が取得できない場合は記録なしとして集計から除外し、その旨を記録する。

## サイジングと台帳（イベント台帳型、EXP-120 / EXP-124 / EXP-139 と同型）

- **枠**: フォワード共通の予算 ¥400,000 を記帳上の枠とする。ペーパーであり実資金は動かさない。
- **1 イベントの金額（想定元本方式）**: 1 イベント = **¥20,000 の想定元本**、株数は 20,000 / 引け価格 で**端数株を許容**する。
- **実弾充足率の観測**: 各イベントについて 引け価格 × 100 株（単元額）を観測項目として台帳に残す。ペーパーの採否・損益には影響しない。
- **同時保有**: 上限は設けない。同日に複数イベントが発生し得るが、全イベントを独立に記録する。
- **台帳**: イベントごとに、イベント日、コード、引け価格、終日VWAP、乖離率、エグジット日（翌営業日）と引け価格、同窓 TOPIX 変化率、コスト別の損益、および次項の実現可能性フィールドを記録する。台帳は追記のみとし、遡及修正をしない。前方実装は引け後スナップショット（`exp144_snapshot.py`、平日16:02頃に当日分足から特徴量を記録）＋夕方 step の `update_fdvwap_ledger()` で行い、台帳は `forward/fdvwap_ledger.csv`、集計は `forward/fdvwap_summary.json` とする。
